## 📋 검토 단계

**상태 전환**: 🔄 진행 중 → 🔍 검토 중 → 피드백 수신 → [수정 필요?] YES: 수정 & 재검토 | NO: ✅ 완료 → Git Commit & PR

### 1단계: 구현 완료 및 검토 요청
- 개발자(Claude)가 Phase 작업 완료
- `review/phase-X-Y-review.md` 문서 작성 (하단 템플릿 참조)
- 상태 업데이트: `🔄 진행 중` → `🔍 검토 중`

### 2단계: 피드백 수신 및 처리 (⚠️ 중요: 자동 반영 금지)
사용자 피드백 수신 시 다음 절차를 엄격히 준수합니다.
1. **분석**: 피드백 내용 정리 및 영향 범위 분석
2. **제안**: 수정 계획을 사용자에게 제시
3. **확인**: 사용자의 반영 여부 및 계획 승인 요청
4. **대기**: 승인 전까지 코드 수정을 진행하지 않음

### 3단계: 수정 반영 (승인 후) 또는 최종 승인
**수정이 필요한 경우**:
- 승인된 계획에 따라 코드 수정
- 기존 `phase-X-Y-review.md` 문서에 피드백 반영 내역 추가 (하단 템플릿 참조)
- 재테스트 수행 및 결과 기록
- 2단계(재검토)로 복귀

**수정이 불필요한 경우**:
- 사용자의 최종 확인 ("승인" 또는 "완료" 코멘트)
- 상태 업데이트: `🔍 검토 중` → `✅ 완료`

### 4단계: Git Commit 및 PR 생성
- **규칙 준수**: [PROJECT_CONTEXT.md - Git Workflow](../../PROJECT_CONTEXT.md#-git-workflow) 참조
- **단위 커밋**: 논리적 단위로 커밋 분리 (예: Logging, Error, EventBus 각각)
- **🚫 금지**: "🤖 Generated with Claude Code" 및 "Co-Authored-By" 태그 제거
- **브랜치**: `dev` 브랜치를 base로 PR 생성 (이전 feature 브랜치는 삭제 금지)
