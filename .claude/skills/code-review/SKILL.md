# Phase 리뷰 시작

구현 완료 후 검토 단계로 전환합니다. `.claude/rules/review-process.md`의 규칙을 따릅니다.

## 작업 순서

### 1단계: 현재 Phase 확인

`.claude/phases/PROGRESS.md`를 읽어 현재 진행 중(🔄) 또는 방금 완료된 Phase를 확인한다.
인자로 Phase 번호가 주어졌다면 그 Phase를 대상으로 한다.

### 2단계: Phase 체크리스트 검증

`.claude/phases/phase-X-*.md`에서 해당 Phase의 작업 항목을 확인하고,
각 항목이 실제 코드에서 완료되었는지 검증한다.

완료 기준을 충족하지 못한 항목이 있다면 사용자에게 알리고 진행 여부를 확인한다.

### 3단계: 리뷰 문서 생성

`.claude/docs/reviews/phase-X-Y-review.md` 파일을 생성한다.
이미 존재하면 덮어쓰지 않고 사용자에게 알린다.

아래 템플릿을 사용한다:

```markdown
# Phase X.Y: [작업명] 🔍

**상태**: 🔍 검토 중 (YYYY-MM-DD)
**우선순위**: [⭐⭐⭐ / ⭐⭐ / ⭐]
**의존성**: [이전 Phase 또는 "없음"]

---

## 📊 구현 현황

### [작업 영역] [상태 기호]
- [주요 구현 사항]

---

## 📝 작업 체크리스트

### 1. [작업 항목]
- [✅/🔄] 세부 사항

---

## ✅ 완료 기준
- [✅/🔄] 기준 항목

---

## 📂 수정/생성된 파일 목록

| 파일 | 작업 | 변경 내용 |
|------|------|-----------|
| `경로/파일명` | 생성/수정/삭제 | 변경 내용 |

---

## 🔍 검토 사항

### 코드 리뷰
- [ ] 아키텍처 레이어 규칙 준수
- [ ] 네이밍 컨벤션 준수
- [ ] 임포트 순서 준수
- [ ] 추가 항목...

### 기능 테스트
- [ ] 핵심 동작 검증
- [ ] 엣지 케이스 처리
- [ ] 추가 항목...

---

## 💡 구현 하이라이트

### 1. [주요 특징이나 결정 사항]
[설명]

---

## 📋 다음 단계

1. [ ] 사용자 피드백 확인 및 승인
2. [ ] 피드백 반영 (승인 후 진행)
3. [ ] Git 커밋 및 PR 생성 (git-workflow.md 규칙 준수)
4. [ ] PROGRESS.md 업데이트
```

### 4단계: Phase 상태 업데이트

PROGRESS.md에서 해당 Phase 상태를 🔄 → 🔍로 변경한다.
phase-X-core.md 등 Phase 상세 문서에도 동일하게 반영한다.

### 5단계: 검토 요청 안내

리뷰 문서 생성 완료 후 사용자에게 다음을 안내한다:
- 생성된 리뷰 문서 경로
- 주요 검토 사항 요약
- 피드백 방법 (피드백 수신 후 즉시 반영하지 않고 수정 계획 제시 → 승인 → 진행)

## 핵심 규칙 (review-process.md 준수)

- **피드백 수신 시 즉시 코드 수정 금지** — 수정 계획 제시 후 사용자 승인을 받아야 한다
- **사용자 명시적 승인 전 리뷰 문서 수정 금지**
- 피드백 → 영향 범위 분석 → 수정 계획 제시 → 승인 대기 → 수정 진행
