# Diff 표시 규칙 (Before/After Presentation)

코드·문서·설정의 변경 제안을 사용자에게 보여줄 때, 빨강(삭제)/초록(추가)이 시각적으로 즉시 구분되도록 ` ```diff ` 코드블록을 사용한다. CommonMark 렌더러는 `-` 로 시작하는 줄을 빨강, `+` 로 시작하는 줄을 초록으로 표시한다.

## 언제 사용하는가

**사용**:
- 기존 파일을 수정할 때 before/after를 함께 보여주는 경우
- 같은 패턴이 여러 곳에 반복되는 변경 (리팩토링, 컨벤션 일괄 변경, 마이그레이션 등)
- 사용자가 "수정 전후", "어디가 바뀌나", "변화를 알아보기 쉽게" 등을 요청한 경우
- 코드 리뷰·PR·설정 변경 제안 등 변경 단위를 강조해야 할 때

**사용 안 함**:
- 신규 파일 전체 작성 — 변경 전이 없으므로 일반 코드블록 사용
- 단순 코드·명령 예시 — before/after 비교 의도가 없는 경우
- 한 줄 미만 변경 — 자연어 한 줄이 더 명확

## 형식 규칙

1. **컨텍스트 줄 포함** — 변경 줄 위·아래에 1~2줄의 unchanged 줄을 둬 위치 식별을 돕는다
2. **앞 공백 1칸 정렬** — ` ` (변경 없음) / `-` (삭제) / `+` (추가) 첫 글자가 같은 열에 정렬되도록
3. **압축 표기** — 표·리스트 전체가 바뀌면 모든 행을 나열하지 말고 `... (N행 동일 패턴)` 처럼 축약
4. **블록 1개 = 변경 단위 1개** — 무관한 변경을 한 블록에 묶지 않고, 파일이나 의미 단위로 분리
5. **블록 밖에 메타 설명** — 대상 파일명·근거·영향 등은 블록 바로 위·아래에 한국어 자연어로

## 예시

대상: 설정 파일의 옵션 객체

```diff
  {
    "name": "example",
-   "version": "1.0.0",
-   "deprecated": true
+   "version": "2.0.0"
  }
```

근거: 버전 업과 동시에 사용하지 않는 필드를 제거.

## 안티패턴

- before와 after를 별개 코드블록 2개로 분리 → 색 구분이 끊기고 줄 단위 비교가 어려움
- 변경 줄 안에 `// 여기 수정` 같은 자연어 설명 삽입 → 설명은 블록 밖에
- 한 블록에 여러 파일의 변경을 묶음 → 파일별로 블록을 나누고 각 블록 위에 대상 파일을 명시
- 컨텍스트 줄 없이 `-`/`+` 줄만 나열 → 어디가 바뀌는지 식별 곤란
