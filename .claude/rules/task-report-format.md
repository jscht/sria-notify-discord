# 작업 완료 보고 템플릿 (Task Report Format)

작업이 끝났을 때 결과를 바로 파악할 수 있도록 정리된 형식으로 보고한다.

## 언제 사용하는가

답변을 쓰기 직전에, 보고할 내용이 "✅ 한 일" 말고 다른 섹션(🧪 검증 / 👀 확인 필요 / ⏸️ 미룬 것 / ⏭️ 진행 위치)에도 들어가는지 판단한다.
- 하나라도 들어가면 → 템플릿을 쓴다
- 없으면 → 기존처럼 2~3줄로 답한다
- 이미 정해진 포맷이 있는 출력(`/pdca status` 대시보드, 에이전트 Output Format 등)은 그 포맷을 우선한다

## 템플릿

```
## 🟢 완료 — <한 줄 결론>          (🟢 완료 / 🟡 부분 완료 / 🔴 실패·중단)

### ✅ 한 일
- <무엇을 + 왜> — `file:line`

### 🧪 검증
- 통과: <명령> (exit 0)
- 미검증: <항목> — <이유>

### 👀 확인 필요
1. [결정] <선택이 필요한 것> — 추천: <안>
2. [검토] <봐주셨으면 하는 변경 지점> — `file:line`

### ⏸️ 미룬 것
- <항목> — <이유> → 제안: [행선지]

### ⏭️ 진행 위치
[3/5] ✅ 1.A → ✅ 2.B → ✅ 3.C → ⬜ 4.D → ⬜ 5.E
다음: 4.D — 진행할까요?
```

## 형식 규칙

1. 빈 섹션은 생략한다
2. 질문은 마지막 줄에 하나만 둔다
3. 🔴일 때는 "한 일" 대신 원인 / 시도한 것 / 막힌 지점 / 제안으로 쓴다
4. PDCA 사이클 중이면 진행 막대에 PDCA 단계를 쓴다 (예: ✅ plan → 🔄 do → ⬜ analyze)
5. [결정] 항목에는 추천안을, [검토] 항목에는 `file:line`을 함께 적는다

## 미룬 작업의 행선지

| 행선지 | 의미 | 기록 |
|--------|------|------|
| [이번 세션] | 지금 작업 순서 안에서 곧 처리 | 진행 막대에 단계로 추가 (파일에 기록하지 않음) |
| [Phase X.Y] | 특정 Phase에서 처리 | todo.md에 `**[Phase X.Y]**` 태그로 기록 |
| [작업명] | Phase와 무관한 작업 묶음 | todo.md에 `**[docs-cleanup]**`처럼 작업명 태그로 기록 |
| [미정] | Claude가 판단할 수 없음 | 👀 확인 필요의 [결정] 항목으로 올림 |

- todo.md 기록은 사용자 승인을 받은 뒤에만 한다
- 같은 항목이 이미 있는지 확인한 뒤 추가한다
- 관련 파일 경로를 꼭 함께 적는다 (나중에 파일 경로로 다시 찾기 위함)

## 관련 TODO 확인 (작업 종류 무관)

큰 작업의 시작과 끝에서, 세션 시작 때 SessionStart 훅이 넣어 준 미완료 목록과 대조한다 (todo.md를 따로 열지 않는다).
- **시작 전**: 관련 항목이 있으면 먼저 알리고 같이 처리할지 묻는다
- **완료 보고**: 해결된 항목이 있으면 👀 확인 필요에 "체크 처리할까요?"로 올린다
- **관련 판단 기준** (우선순위 순): ① 수정 파일 경로 일치 ② 태그 = 작업명/브랜치명 ③ `[Phase X.Y]` = 현재 Phase

## 안티패턴

- 미룬 항목을 묻지 않고 todo.md에 바로 추가
- 검증하지 않은 것을 "완료"로 표기
- 질문을 본문 중간에 흩어 놓기
- 내용 없는 섹션을 "없음"으로 채워서 남기기
