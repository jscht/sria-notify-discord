## 2. 구현 요약

### 2.1 주요 변경사항
1. **구독 형식**: `regions`·`sources`를 `ALL` 또는 `SELECTED + 값 목록`으로 저장한다. 옛 문서는 읽을 때 새 형식으로 바꾸고, `sources`가 없는 옛 문서는 모든 소스를 받는 것으로 읽는다.
2. **소스 설정**: `SOURCE_CONFIGS`에 표시 이름, 링크, 노출 여부(`userFacing`), 고유 지역 묶음(`ownRegionGroup`)을 둔다.
3. **공통 표시 형식**: sria·elias가 각자 `toDisplay()`를 구현한다. "전체 공고" 링크는 `SourceConfig.url`을 쓴다.
4. **elias 정리**: `temp`를 `elias`로 바꿨다. 모집 기간은 12시간이고, 상태는 "접수중"에서 "종료"로 한 번만 바뀐다.
5. **알림 전용 스케줄러**: 매일 06~20시 짝수 정시(한국 시간)에 사이트를 갱신하고, 지난 알림 때 목록과 비교해 바뀐 공고가 있는 구독자에게 DM 한 통을 보낸다. 사이트 갱신(sria 120분, elias 30분)은 저장과 변경 감지만 한다.
6. **예약 작업 목록 `SCHEDULED_JOBS`**: 운영 함수 3개와 로컬 실행이 같은 목록을 쓴다. 같은 작업이 겹쳐 돌면 Redis 락으로 한쪽만 실행한다.
7. **구독 UI**: 설정 관리 화면 아래에 지역 설정과 사이트 설정을 둔다. 사이트 설정은 "일반 공고"·"elias 공고" 켜기/끄기이고, 첫 구독은 일반 공고만 켠다. 지역은 켜진 공고 기준으로 보여 주고 공고별로 2개까지 고른다.
8. **목록 표시**: 사이트별로 묶고, 제목에 `[지역][상태]`를 붙인다. DM은 접수중 → 발표중 → 종료, 같은 상태 안은 시작 시점 최신순이다.
9. **공고 조회**: 저장 경로를 `syncRecruits`로 통일했고 Firestore 목록은 읽기만 한다. 공고가 0건인 사이트는 Redis에서도 지운다.

### 2.1.1 런타임 검증 뒤 변경 (2026-11-03 ~ 11-05)
- 사이트 선택 메뉴와 첫 구독 사이트 질문을 공고 묶음 켜기/끄기로 바꿨다.
- 정렬에 시작 시각까지 비교한다. elias 공고는 기간이 12시간이라 날짜만으로는 새 공고가 위로 오지 않았다.
- 권역을 고른 뒤 시 메뉴가 멈추는 문제를 "메뉴 잠금 → 시 메뉴 교체" 두 단계로 고쳤다. 분석은 [`loading-stall-analysis.md`](loading-stall-analysis.md).
- 지역 모드가 "모든 지역"일 때 열어 둔 옛 메시지에서 지역을 편집하면 저장하지 않고 안내 화면을 보여 준다.
- 첫 구독은 모든 공고 대신 일반 공고만 켠다.
